## 一、目的与边界

**目的**：在商业化（应用商店上架、对外收费、融资尽调）之前，确认 JU 的核心实现
**不落入他人在先有效专利的保护范围**，并为可能的设计绕行（design-around）提供依据。

**边界（本框架不覆盖）**：

- 商标（见 [`C1-TRADEMARK.md`](./C1-TRADEMARK.md)）与著作权（第三方依赖见 [`../LICENSE-AUDIT.md`](../LICENSE-AUDIT.md)、[`../SBOM.json`](../SBOM.json)）；
- 商业秘密与开源许可证合规（GPL/AGPL 传染性另有审计口径）；
- 已过期专利、已放弃专利、以及非实施主体（NPE）的诉讼风险评估（另行立项）。

**FTO 的时点纪律**：FTO 结论**仅对检索日有效**。建议在以下节点重跑：
① 首次商业收费前；② 大版本架构变更（如引入 CRDT / 云端同步）；③ 融资尽调；④ 每 12 个月例行复检。

## 三、重点排查对象（三组）

### 3.1 Notion —— Block 模型

| 关注点 | 被怀疑的权利要求方向 | 与哪条本方特征相关 |
| --- | --- | --- |
| 文档由「块（block）」组成，块有类型与父子关系 | 一种文档编辑系统中基于块的文档结构 | F1 |
| 块类型转换（段落 ↔ 标题 ↔ 列表 ↔ 待办） | 块类型间转换与属性继承 | F1 / F2 |
| 拖拽重排与跨层级移动 | 树形结构的拖放重排 | F1 |
| 同一数据的多视图（表格 / 看板 / 日历 / 画廊） | 数据源 + 视图配置的分离 | **F2（最高相关）** |
| 实时协作中的块级并发编辑 | 块级同步与冲突消解 | F4（本方为 LWW，差异明显） |

### 3.2 Roam Research —— 图谱与双向链接

| 关注点 | 被怀疑的权利要求方向 | 与哪条本方特征相关 |
| --- | --- | --- |
| 双向链接（backlink）自动索引 | 反向引用索引的自动生成与呈现 | F1（本方无自动反链索引，需确认） |
| 块引用（block reference）与嵌入（embed） | 对文档片段建立稳定引用并在多处渲染 | F1 |
| 图谱视图（节点-边可视化） | 由引用关系生成图结构并布局 | **F2（图谱视图）** |
| 大纲折叠状态与会话恢复 | 层级结构的视图状态持久化 | F7（渲染态，非专利点） |

### 3.3 Airtable —— 多维表格

| 关注点 | 被怀疑的权利要求方向 | 与哪条本方特征相关 |
| --- | --- | --- |
| 记录（record）/ 字段（field）/ 视图（view）三层模型 | 结构化数据表的视图配置方法 | **F2（最高相关）** |
| 关联记录（linked record）与查找字段（lookup/rollup） | 跨表引用与派生字段计算 | F1 + F2 |
| 公式字段 / 计算字段的增量重算 | 依赖图的增量求值 | F3（结构共享，可作差异点） |
| 视图级筛选/排序/分组配置的持久化 | 视图配置与数据分离存储 | F2 |

**三者的共同风险面**：都指向同一件事——**「同一份数据 + 多种视图配置」**。
JU 的 F2 与 F3 的组合（投影 + 结构共享）是主要比对目标；F4（LWW）与 F5（本地优先、无协作服务端）
是**显著差异特征**，应在每份 claim chart 的「差异要件」列中重点记录。

### 3.4 三大功能的针对性回避策略（Draft v0.2 · 2026-10-24）

> 本节把「反链 / 多维表格 / 思维导图」三个高风险功能拆成可执行的设计绕行条目。
> 每条都对应**代码中已存在的实现差异**（不是口头承诺）；「待加固」项列入 §八 待办，
> 完成后回填「代码证据」列。引用行号为编写日快照，复核时以函数名定位为准。

#### 3.4.1 反链（Backlinks）

| 对方可能主张的要件 | JU 当前实现（差异事实） | 回避策略 | 代码证据 |
| --- | --- | --- | --- |
| 写入时**自动生成并持续维护**反向引用索引（索引是一等数据） | JU **没有反链索引、没有边表、没有写入钩子**；`backlinksOf()` 仅在右栏渲染时对 `state.nodes` 做一次全表扫描，结果只活在本次渲染调用栈 | 维持「按需计算、用完即弃」：不把反链结果写入 `localStorage` / SQLite，不暴露增量更新 API | `src/ui/rightbar.ts:400`（`backlinksOf`） |
| 双向链接作为独立数据结构（link table / edge store） | 链接只存在于节点文本的 `[[标题]]` 语法中，运行时用正则解析；节点表不存任何引用来回关系 | 「文本内联引用 + 渲染期解析」，数据层保持单树；不新增 `edges`/`links` 持久化表 | `src/ui/rightbar.ts:387`（`outgoingLinksOf`）、`WIKI_RE` 匹配 |
| 反链面板**实时增量刷新**（监听编辑事件逐个更新） | 面板随 `renderMain()` 重建，按「当前文档子树标题集合」匹配并**排除自身子树**，无后台订阅、无增量补丁 | 保持整块重算；若未来量大，改为「展开右栏才查 + 按 commit 版本整块失效」，仍不做逐条增量 | `src/ui/rightbar.ts:427`（`renderBacklinkPanel`） |
| 「被引用即建立图节点」的图谱联动 | 图谱视图是**按引用关系临时构建**的渲染投影（F2），不把反链固化为图模型 | 图谱每次渲染重建、不落盘；与反链面板不共享持久化结构 | `src/views/graph.ts`（`GraphRenderer`） |

**待加固（列入 §八）**：把 `backlinksOf()` 的「全表扫描」显式注释为**渲染期查询**，禁止任何模块缓存反链结果；
若产品后续要「全局反链」，采用「按需查询接口 + 不落盘」形态，并在 FTO 报告中单独说明。

#### 3.4.2 多维表格（Database / Views）

| 对方可能主张的要件 | JU 当前实现（差异事实） | 回避策略 | 代码证据 |
| --- | --- | --- | --- |
| 独立的 record / field / view 三层元数据模型 | JU 的「行」就是同一棵节点树的子节点，列值放在节点的 `db` 字典；**没有独立 record 表、没有 schema 服务端** | 坚持「单树 + 字段名字典」；不引入与节点树并行的表模型 | `src/views/database/formula.ts:39`（`DbRow` 即表节点） |
| 视图配置作为**可序列化的一等对象**持久化（view config） | 表格 / 看板 / 画廊 / 时间线 / 图表都是**渲染函数**；筛选与排序参数存于 `ui.dbFiltersMap` / `ui.dbSortsMap`（UI 偏好），不作为独立视图对象落盘 | 把筛选/排序明确定位为「会话/UI 状态」：不提供视图 CRUD、不把视图配置写入数据快照 | `src/views/database/render.ts:313`（`dbRowsApply`）、`:334`（`renderDatabasePage`） |
| 依赖图 + 脏标记的**增量重算**（公式字段） | 公式字段在渲染 / 取值时**按行即时求值**，用 `_formulaDepth` 限制递归深度；没有持久化依赖图、没有跨行脏传播 | 保持「即时求值 + 深度上限」；不缓存跨行依赖关系 | `src/views/database/formula.ts`（`dbFormulaEval` / `_formulaDepth`） |
| 不同视图共享同一「数据源绑定层」并由视图配置驱动 | JU 的视图是 `switch` 分发到不同渲染函数，参数来自 UI 状态；**数据绑定方式为「节点树直读」** | 渲染函数之间不共享可配置的 binding 描述对象；避免「view descriptor → renderer」的专利化表达 | `src/app/render.ts`（视图分发）、`src/views/database/render.ts` |

**待加固（列入 §八）**：核实 `dbFiltersMap` / `dbSortsMap` 的落盘路径（`saveUI()` 是否持久化）。
若已持久化，需在文档与代码注释中统一表述为「**UI 偏好**（非视图对象）」，并评估是否改为会话级；
这是本功能剩余的最高风险点。

#### 3.4.3 思维导图（Mindmap）

| 对方可能主张的要件 | JU 当前实现（差异事实） | 回避策略 | 代码证据 |
| --- | --- | --- | --- |
| 递归计算**每棵子树的包围盒**再做二次平衡（Reingold–Tilford 类） | JU 采用**单次深度优先前序 + 叶子游标**：`cursorY` 顺序分配叶子 y，父节点 y 取首末子节点中点，`x = depth * GX`；**不计算子树包围盒、不做二次平衡/迭代求解** | 保持线性前序遍历；不引入「包围盒 + 二次布局」步骤 | `src/views/mindmap.ts:137`（`layoutMindmap`） |
| 整图布局求解后**全量重排重绘** | 渲染端用**脏节点集合 + rAF 合批 + 视口裁剪**做增量绘制；布局只产出坐标数组，不做图求解 | 保持「布局=纯函数坐标投影、渲染=差分」的两段式；不引入布局求解器 | `src/views/mindmap.ts:378`（`_mmMeasure`）、`:446`（`_mmFlush`）、`:456`（`_mmSchedule`） |
| 独立的图模型 / 边表（节点与连线一等存储） | 连线由 `children` 关系**渲染期推导**；折叠态是节点字段 `collapsed`，不进入任何图算法输入 | 不持久化边表；折叠态保持为普通节点字段 | `src/views/mindmap.ts:146`（`n.collapsed ? [] : n.children`） |
| 特定「中心向两侧展开」的对称布局 | JU 为**单侧从左到右**（`x = depth * GX`），无左右对称分支、无重心约束 | 保持单侧布局；如需双向展开，采用独立布局函数并保留单侧实现作为默认 | `src/views/mindmap.ts:144` |

**待加固（列入 §八）**：为 `layoutMindmap` 增加「布局算法可插拔」接口（默认保持当前线性前序），
在被具体专利对照时可切换到非递归 / 非对称实现，且不改变数据模型。

#### 3.4.4 三功能风险速览

| 功能 | 最高相关特征 | 当前差异强度 | 建议风险等级 | 首要动作 |
| --- | --- | --- | --- | --- |
| 反链 | 自动反链索引的生成与呈现 | **强**（无索引、无持久化、按需扫描） | 绿 → 黄（待检索确认） | 固定「渲染期查询」表述与代码注释 |
| 多维表格 | 视图配置持久化 + 依赖图增量重算 | **中**（筛选/排序为 UI 状态，需核实落盘） | 黄 | 核实 `dbFiltersMap/dbSortsMap` 落盘；必要时改会话级 |

**判定规则（必须遵守）**：

1. **全面覆盖原则**：只有**全部**要件都被本方实现覆盖，才构成字面侵权；
   **任一要件不满足即不落入**（all-elements rule）。
2. **等同原则**：要件虽字面不同，但「手段—功能—结果」实质相同且对本领域技术人员显而易见时，
   可能构成等同；此时不得直接判「不落入」，须转入 §5.3。
3. **禁反言**：专利权人在审查/无效程序中已放弃的范围，不得再通过等同原则主张。
4. **差异要件必须留证**：判「不落入」的每一件，都要指出**具体差异要件编号**与其技术依据。

## 六、风险分级与处置

| 等级 | 判据 | 处置 |
| --- | --- | --- |
| **红** | 存在有效授权专利，且本方**全部要件字面落入** | 立即设计绕行或取得许可；在完成前不扩大商业分发 |
| **橙** | 存在审中申请，权利要求可能覆盖本方核心特征 | 监控审查过程（公开文本），预先准备绕行版本 |
| **黄** | 仅等同风险，或要件存在可主张的实质差异 | 保留技术证据（本文档 §5.2），律师出具意见 |
| **绿** | 无相关在先权利，或对方已失效 | 归档，纳入 12 个月例行复检 |

**本方既有优势（可在比对中主张的差异点）**：

- F4 采用 **LWW** 而非 CRDT/OT，且**无实时协作服务端**——多数协作类专利以「服务端合并」为要件；
- F5 **完全本地、无账号、无云端**——「服务器/远程存储」要件常为独立权利要求必要技术特征；
- F3 **结构共享的不可变提交**（persistent data structure）与 Airtable 的「依赖图增量重算」在实现路径上不同；
- F2 的视图是**渲染投影而非持久化的视图配置对象**（需在代码证据中确认：视图配置是否落盘、是否为独立可序列化对象）。

> 特别提醒：§六 末尾第 4 条是本方最容易被质疑的点。若 JU 在 `localStorage` 中持久化了
> 「视图配置」（筛选/排序/分组），则与 Airtable 类专利的「视图配置持久化」要件更接近，
> 需在 FTO 报告中单独展开。**这是本次分析必须优先核实的第一项。**
