## 0. 一句话结论

目标生态位 = 本地优先/离线 + 数据主权（Markdown/Git/外部编辑器可管理） + 端到端加密 + 开箱即用的一体化个人工作台（大纲×日历×多维表格×双链×导图×提醒×番茄） + 移动端/PWA + 本地 AI，且不依赖插件生态、账户体系与云协作。



JU 的短板不在“功能数量”，而在 **闭环**：

> **链接不成网、提醒不落地、移动端进不去、数据可移植性不足。**

补上这些洞，再叠加 **本地优先 + 加密 + 日历驱动 + AI + 数据主权**，JU 才有机会在 Notion（太重）与 Obsidian（太技术）之间，切出“个人工作台”的独特生态位。

## 1. 定位与边界

### JU 是什么

- **本地优先的个人工作台**，不是单纯的“知识库”，也不是“企业协作平台”。
- 核心能力骨架：大纲 + 日历 + 多维表格 + 思维导图 + 图谱 + Word/演示 + 标签 + 历史 + 加密。
- 优势：单文件、离线可用、隐私加密、功能密度高、桌面 SQLite 适配、导入导出较全、视图多、日历/待办/大纲联动。

### JU 不是什么

- 不是“更好的 Obsidian”：Obsidian 是知识库，JU 是工作台。
- 不是“更好的飞书”：飞书是企业协作平台，JU 是个人掌控工具。
- 不是必须做在线协作/云同步/发布平台。若坚持本地单机定位，应优先做 **数据主权、离线可用、可移植、可长期保存**。

### 与竞品关系

- **Obsidian**：场景互补。极客/愿配置者继续用 Obsidian；要开箱即用、数据安全、一体化体验者用 JU。
- **飞书**：互补而非替代。白天用飞书团队协作，晚上用 JU 管理个人项目、笔记和日程。
- **幕布/Notion/滴答清单/Things**：JU 在大纲、日历、表格、加密上有融合优势，但在协作、数据库深度、提醒闭环、移动端、AI、插件生态上仍有明显缺口。

### 2.4 竞品对标（详细，大纲格式列出）

#### 2.4.1 Obsidian
- **强项**
  - 本地 Markdown 文件，数据所有权完整。
  - 双向链接、关系图谱、Canvas。
  - 1000+ 社区插件，生态极厚。
  - 个人使用免费，无功能限制。
- **痛点**
  - 开箱即用差，需自行设计目录、插件、工作流。
  - 插件依赖症，停更/冲突会断工作流。
  - 原生协作几乎为零，Sync 贵。
  - 移动端体验一般，输入法兼容有 Bug。
  - 数据库能力弱于 Notion，大型库搜索排序弱。
- **JU 差异**
  - JU 原生集成 9 类视图，无需插件。
  - 桌面 Tauri + SQLite，本地优先，目标 3–10 万节点流畅。
  - 日历、多维表、番茄钟、加密内置。
  - 短板：外部 Markdown 编辑、文件库、插件生态、移动端。

#### 2.4.2 飞书
- **强项**
  - 企业协作、日历、多维表格、AI、移动端完整。
  - 组织流程、权限、共享、评论成熟。
- **痛点**
  - 数据主权在企业，不在个人。
  - 个人版 100GB，聊天 18 个月清理。
  - 多维表基础免费版单表 2000 行，单文件 300 表。
  - 知识被聊天和多入口分散。
  - 偏结构化 Wiki，缺双链和关系图谱。
- **JU 差异**
  - JU 数据本地、用户完全掌控，无硬限。
  - 个人驱动，不依赖云端和组织体系。
  - 9 类视图融合，单 HTML/本地应用交付。
  - 不追协作，专注个人项目、笔记、日程闭环。

#### 2.4.3 Workflowy
- **强项**
  - 极简大纲鼻祖，打开即用，学习成本近零。
  - 无限嵌套列表，标签灵活。
  - 2026 新增 Tables/Panes/Calendar。
- **痛点**
  - 免费版限 100 条/月。
  - 无数据库、无高级格式化。
  - 云端存储，数据不在本地。
  - 列表增长后导航困难。
- **JU 差异**
  - 保留无限嵌套大纲，但本地运行、无条数硬限。
  - 内置日历、多维表、导图、双链、加密。
  - 数据可导出，不依赖账户体系。

#### 2.4.4 Dynalist
- **强项**
  - 免费版不限文档和条目数。
  - 内部链接、Markdown、日期、标签、复选框。
  - 界面美观，操作流畅。
- **痛点**
  - 不支持团队协作。
  - 无 AI。
  - 无看板/时间线等可视化。
  - 相比 Notion/Obsidian 显陈旧。
- **JU 差异**
  - JU 有多视图、日历、数据库、导图、图谱。
  - 本地优先 + 加密 + 离线。
  - 保留大纲流畅交互，并扩展为个人工作台。

#### 2.4.5 幕布
- **强项**
  - 大纲一键生成思维导图，上手极低。
  - 全平台云端同步，社区分享生态。
  - 2026 新增 AI 智能创建、文档透视图。
- **痛点**
  - 文本排版有限。
  - 专业思维导图能力不足。
  - 高级功能需订阅。
  - 云端依赖。
- **JU 差异**
  - 大纲↔导图双向实时同步，编辑导图即编辑大纲。
  - 完全离线，本地加密。
  - 导图可 SVG/PNG 导出，节点对应大纲节点。

#### 2.4.6 Logseq
- **强项**
  - 完全开源 AGPL-3.0。
  - 本地优先，Markdown 存储。
  - 块级引用与日记流优秀。
  - 大纲式编辑体验好。
- **痛点**
  - 从 Markdown 转向 SQLite，文件兼容性不确定。
  - 数据目录结构可读性差。
  - 移动端体验一般。
- **JU 差异**
  - JU 当前保留结构化本地存储 + 多格式导出。
  - 有日历、多维表、番茄钟、加密。
  - 短板：块级引用、日记模式、外部 Markdown 文件库。

#### 2.4.7 Roam Research
- **强项**
  - 首创双向链接范式。
  - 块级引用粒度。
  - 日记流工作流。
  - 可编程 Roam/js，AI 集成。
- **痛点**
  - 无免费版，$15/月贵。
  - 闭源，数据在 Roam 服务器。
  - 大图谱性能下降，50k+ 块搜索变慢。

## 3. JU 的核心不足

### 3.1 链接系统仍有缺口

- 反链面板已有，但缺 **未链接提及**（文中出现标题但未加 `[[ ]]` 时不会提示补链）。
- 无 **块级引用/嵌入**，缺 Notion synced block、Obsidian block ref 对应物。
- 图谱不能导航：无 hover 预览、局部图谱、按标签/文件夹过滤。
- `byTitle` 用纯文本做键，重名节点会静默丢边，改标题后旧链接不自动更新。

### 3.2 数据库“能算但不够深”

- 公式引擎已有，但缺 **关联字段 Relation、滚动汇总 Rollup、Lookup**。
- 筛选已有 OR 分组，但缺“筛选器保存为视图”。
- 缺数据库日历视图（表格行无法铺到日历格子）。
- 看板只能按“状态”分组，不能按任意 select 字段分组。

### 3.3 提醒闭环不完整

- 系统通知已有（到点提醒 + 30s 轮询 + 角标）。
- 但缺：稍后提醒、延后 10 分钟、明天再说、声音提醒、邮件提醒。
- 番茄钟和任务孤立，不能“开始专注 → 自动关联某条待办”。

### 3.4 移动端与 PWA 几乎为零

- 响应式断点已有（1366/1100/768/640/480px），但侧栏、拖拽、右键菜单触屏体验差。
- 无 `manifest.json` + Service Worker，不能安装到主屏，不能离线启动。
- 依赖大量 mouse 事件，触屏需改 pointer 事件（部分已改，未全覆盖）。

### 3.5 搜索与命令面板偏弱

- 搜索是纯子串匹配 + 高亮，无高级语法、结果分组、搜索历史、保存搜索。
- `Ctrl+K` 绑给搜索框，无命令面板。Obsidian/Notion 的 `Ctrl+P` 是核心效率入口。

### 3.6 数据安全有余，可靠性不足

- 加密做得不错（AES-GCM + PBKDF2 600k + 加密自动备份到 IndexedDB）。
- 但 `localStorage` 4.5MB 上限是硬伤，超了只 toast 报错，无迁移路径（桌面版走 SQLite 无此问题）。
- 版本快照只存文档子树，恢复是整篇覆盖，无 diff、无节点级恢复。
- 快照有自动节流（空闲 2s + 最小间隔 60s），但无“手动打里程碑”按钮。

### 3.7 横切短板

- **同步协作**：BroadcastChannel + storage + LWW，无 CRDT，复杂并发可能丢更新；无云同步、实时协作。
- **加密**：无多设备密钥交换、密钥恢复、生物识别、零知识同步。
- **搜索**：无全文索引、语义搜索、保存搜索、高级过滤。
- **性能**：大库仍可能 O(n) 扫描；无 Worker 搜索/计算（图谱有 Worker，搜索无）。
- **插件/API**：无，生态缺失。
- **AI**：无自然语言输入、摘要、自动标签、语义搜索。
- **可访问性**：键盘导航不完整（已有部分 roving tabindex），焦点管理可提升。
- **国际化**：中文为主，无多语言、多地区日历。
- **模板**：简单树模板，无变量、日期公式、条件、模板市场。
- **标签**：标签树 + 颜色，无层级标签、标签组、批量管理。
- **图谱**：仅 wiki 链接图，无过滤、聚类、局部图、时间轴。

## 4. 创新机会与优先级

### P0：短平快，1–3 天可做

1. **命令面板 `Ctrl+P`**：把新建文档、切换视图、导出、加标签、开番茄钟注册成命令。
2. **反链面板补全**：右侧栏已有反链，补“未链接提及”一键补链。
3. **提醒闭环补全**：系统通知已有，补“稍后提醒/延后 10 分钟/明天再说”。
4. **数据库日历视图**：复用 `renderCalendarPage`，把表格行按时间字段铺到月历。
5. **数据库字段增强**：公式引擎已有，补 relation/rollup/lookup 三类字段。

### P1：中等投入，1–2 周

6. **全局快速捕获浮窗**：类似 Things Quick Entry，`Ctrl+Shift+Space` 落进收件箱。
7. **PWA 化**：`manifest.json` + Service Worker，`localStorage` 迁移 IndexedDB，解决移动端、离线、4.5MB 上限。
8. **块级引用**：`((nodeId))` 语法，嵌入目标节点内容，编辑同步。
9. **每日笔记/日记模式**：左侧“今天”，自动创建 `2026-09-24` 文档，聚合当天待办和修改。
10. **任务依赖与关键路径**：数据库加“前置任务”关联字段，看板/时间轴显示依赖线。

### P2：长期差异化

11. **AI 层**：自然语言建库、节点摘要、智能标签、周报生成、语义搜索、RAG 本地 LLM。
12. **端到端加密协作（可选实验/远期）**：WebRTC + 服务端只存密文、不依赖账户体系，做“私人小团队”加密协作；定位为远期探索项，不违背本地单机定位。
13. **插件系统**：暴露 `registerView`、`registerCommand`、`onNodeChange`，让用户写视图/导入器。
14. **手写/白板画布**：思维导图 + 无限画布 + 手写笔迹，做视觉思考场景。
15. **本地文件系统知识库**：数据映射为 Markdown + 附件，用户可用 Git、Obsidian、VS Code 管理。
16. **统一时间操作系统**：日历 + 任务 + 番茄 + 习惯 + 日记 + 时间块统一。
17. **自动化规则引擎**：IF 条件 THEN 动作，如“标签 #重要 且 截止日 < 3 天 → 置顶 + 提醒”。
18. **集成生态**：Readwise、Zotero、GitHub、Todoist、Notion、Obsidian、Evernote 导入；浏览器剪藏、邮件转任务、语音转笔记。

## 5. 本地单机定位下的取舍

### 不需要做的

- 在线分享/协作：分享链接、权限、评论、实时协作、云同步，依赖服务器和账户体系，违背本地单机定位。
- 账户体系、在线发布、访客链接、@提醒。
- 不要把“分享平台”作为独立产品线。

### 需要做的

- **导出与交换**：Markdown + 附件打包、单文件 HTML、PDF 打印优化、加密 ZIP、ICS、OPML、Excel。
- **数据可移植**：让数据可被 Git、Obsidian、外部编辑器管理。
- **数据主权**：如果数据只能 JU 自己读，它只是私有数据库应用；如果能被外部工具管理，才真正兑现“本地单机”价值。

### 为什么数据要可被外部管理

- 避免供应商锁定。
- 长期可读：纯文本/Markdown 几十年后仍可读。
- 版本控制与审计：Git 提供历史、diff、分支、回滚、冲突合并、远程备份。
- 与现有工作流集成：Obsidian、VS Code、Typora、Zotero、静态站点生成器、脚本。
- 备份与迁移极简：复制文件夹、rsync、云盘、U 盘、NAS、Git。
- 信任与隐私：明文 Markdown + 可选加密，用户能审计。
- 借用生态，降低开发成本。
- 降低 JU 自身风险：最坏情况只丢界面，数据还在。
- 聚焦核心：JU 做更好的“大纲+日历+数据库交互层”，存储/版本/发布交给文件系统、Git、Obsidian。

### 可选的成熟集成方案（集成方向见 P2 第 18 项）

> 本节不再单独列表；Readwise/Zotero/GitHub/Todoist/Notion/Obsidian/Evernote 等集成方向见 **4. P2 第 18 项**。核心结论如下：
> **建议**：若最看重“数据可被 Git/Obsidian/外部编辑器管理”，**Obsidian + 插件是最成熟方案之一**（Logseq 同样支持 Markdown 外部编辑与 Git 管理）。JU 可不自建生态，而是把 Obsidian 或 Markdown 文件夹作为“外部数据源”对接，专注做更好的交互层。
> **JU 的“外部可编辑”补强路径**：

- **短期（P1）**：导出 Markdown + 附件打包 ZIP，支持增量导出到指定文件夹。
- **中期（P2）**：数据层映射为 Markdown 文件目录（每节点一个 `.md`，附件单独存放），用户可用 Git/Obsidian/VS Code 直接管理。
- **长期**：双向同步——外部编辑器改动 Markdown 后，JU 启动时自动合并（节点级 LWW + 墓碑删除）。

## 6. 最终总结

JU 现在的优势是 **功能密度 + 本地隐私 + 加密 + 一体化视图**。
短板是 **块级模型、文件库、双链深度、数据库关系、提醒闭环、移动端、本地 AI、性能与可访问性**。
在本地单机定位下，不必追在线协作和分享平台，而应优先兑现：

> **数据主权、离线可用、可移植、可长期保存。**

如果数据只能被 JU 自己读，它本质上是一个私有数据库应用；
如果数据能被 Git、Obsidian、外部编辑器管理，它才真正成为“数据属于用户的本地单机工具”。
发布不是终点，是获得真实反馈的起点；但数据安全是底线，不是迭代项。
**先发最小可信版本，别发半成品；先让一小群人用起来，再慢慢改好。**

**JU 的精准市场定位**：面向个人知识工作者的“本地优先一体化工作台”。与各对标产品的关系并非替代，而是 **场景聚合**——用户不需要在大纲工具、笔记软件、日历应用、数据库工具和番茄钟之间切换，所有能力在同一个离线环境内闭环。核心用户画像：重视数据主权与隐私、习惯大纲式思维、需要日历+数据库+双向链接协同工作、不依赖团队协作的个人用户。
在该定位下，JU 最直接的竞争对手是 **Obsidian**（本地优先+双向链接，但缺少日历/数据库/番茄钟）和 **Logseq**（大纲+本地优先，但数据库能力弱于 JU、无日历和番茄钟）。JU 相对于二者的优势在于 **开箱即用的完整度**——无需插件配置即可获得日历、多维表格、番茄钟等能力；劣势在于 **生态厚度**——Obsidian 的插件生态和 Logseq 的社区活跃度是 JU 短期内难以匹敌的。
