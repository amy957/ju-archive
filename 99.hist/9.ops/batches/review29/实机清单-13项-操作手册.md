# 13 项桌面实机操作手册（review29 收口用）

> 目的：把「未验证」的 13 项变成可照着点、可判过、可留证的清单。
> 被测件：`99.hist/8.rel/v2.1.0/JU-v2.1-win-x64.exe`（exe 7,335,424 B）
> 铁律：**全部在一个干净的 Windows 用户或虚拟机里做**，不要用日常账号的真实数据。

---

## 0. 环境准备（只做一次）

1. 新建 Windows 本地用户 `juqa`（或开一台干净 VM），不要登录日常账号。
2. 把整个 `99.hist/8.rel/v2.1.0/` 目录拷到 `D:\juqa\v2.1.0\`（**不要**在 `E:\APP\归档` 里直接跑，避免任何沙箱/同步盘干扰）。
3. 记录初始状态：

```powershell
# 数据目录应为空或不存在
dir "$env:APPDATA\com.ju.app"
dir "$env:LOCALAPPDATA\com.ju.app"
```

4. 建证据目录：`D:\juqa\evidence\`，每项一个子目录，命名 `P-04`…`P-16`。

**判定记录格式**（每项写一个 `结果.md`）：

```
项目：P-xx
开始时间：2026-11-xx hh:mm
exe 哈希：sha256sum D:\juqa\v2.1.0\JU-v2.1-win-x64.exe
步骤：1..n 逐条
断言结果：通过 / 失败（贴关键输出）
截图：01.png 02.png
结论：通过 / 失败 / 阻塞
```

## P-04 加密重启完整链（ISSUE-101）

**前置**：P-05 已通过（能落盘）。

1. 启动 exe → 新建文档 → 输入 3 个节点（内容含中文 + 英文 + 数字，便于肉眼比对）。
2. 打开「设置」→ 开启加密 → 设置密码（例如 `Ju-Test-2026!`）。
3. 完全关闭应用（点关闭按钮，等 3 秒确认进程退出）。
4. 用记事本打开 `%APPDATA%\com.ju.app\ju_store.json`：
   - **断言 A**：文件里**不含**你刚输入的任何明文节点文字。
   - **断言 B**：存在 `encStore` 字段（密文）。
5. 重新启动 exe → 输入同一个密码解锁。
   - **断言 C**：3 个节点原样出现，层级不变。
6. 再关闭、再启动一次（第二次往返）。
   - **断言 D**：仍能解锁，无「解密失败」。

**留证**：步骤 4 的 json 截图（含 encStore 但看不到明文）、步骤 5 的界面截图。
**失败判定**：出现明文即 Critical；解锁失败即 Critical。

## P-05 明文落盘（ISSUE-102）

**前置**：全新数据目录。

1. 启动 exe → 新建文档 → 输入节点 `P5-明文-20261112`。
2. 等 2 秒（防抖落盘）→ 关闭应用。
3. 打开 `%APPDATA%\com.ju.app\ju_store.json`。
   - **断言 A**：`nodes` 中能找到 `P5-明文-20261112`。
   - **断言 B**：文件 mtime 是「刚刚」。

**留证**：json 片段截图 + `dir ju_store.json` 的时间列。
**说明**：本项我在沙箱里曾误判为失败，实为终端沙箱拦截；你在正常账号下应当直接通过。

## P-06 密文备份 5 份轮转（ISSUE-103）

**前置**：P-04 已开启加密。

1. 加密态下连续「编辑 → 关闭 → 启动 → 编辑 → 关闭」循环 **6 次**（每次改一个节点）。
2. 查看 `%APPDATA%\com.ju.app\backups\`。
   - **断言 A**：备份文件数量 **≤ 5**（轮转生效，不是无限增长）。
   - **断言 B**：最新的备份能反映最后一次编辑。
3. 取一份备份，确认是 `JU-备份-YYYY-MM-DD_N.json` 命名且内含 `encStore`（密文，非明文）。

**留证**：`dir backups` 前后对比截图。
**失败判定**：>5 份不清理 = High；备份是明文 = Critical。

## P-07 拖拽 / 置顶 / 窗口按钮（ISSUE-104）

1. 点「置顶窗口」→ 用别的窗口覆盖，确认 JU 始终在最前 → 再点一次取消。
2. 点「最小化」→ 任务栏恢复 → 窗口状态正确。
3. 点「最大化」→ 再点还原 → 布局不错位（左右栏、大纲、右侧按钮都在）。
4. 拖拽窗口边缘缩放 → 大纲区域自适应，无横向滚动条。
5. 拖动顶部空白区移动窗口 → 跟随鼠标，不卡顿。
6. 拖拽节点 `⋮⋮` 手柄上下移动 → 节点落到目标位置，层级正确。

**留证**：置顶前后各一张截图 + 一段 10 秒录屏（拖拽）。
**失败判定**：置顶失效 / 最大化后布局错乱 = Medium。

## P-08 NSIS 安装 / 卸载（ISSUE-105）

**前置**：干净机器（VM 最佳）。

1. 运行 `JU_2.1.0_x64-setup.exe` → 一路默认安装。
2. **断言 A**：安装目录有 `JU.exe`（或产品名 exe），版本 2.1.0。
3. 从开始菜单启动 → 能正常打开（无 WebView2 报错）。
4. 控制面板卸载 → **断言 B**：程序目录清空。
5. **断言 C**：`%APPDATA%\com.ju.app\ju_store.json` **保留**（卸载不删用户数据）。

**留证**：安装向导截图、安装目录列表、卸载后目录列表。
**失败判定**：卸载删掉用户数据 = Critical；卸载残留程序文件 = Medium。

## P-09 强杀恢复（ISSUE-106）

1. 新建文档 → 输入 `P9-强杀前-ABC` → 等落盘（2 秒）。
2. 再输入 `P9-强杀中-XYZ`，**立刻**执行强杀：

```powershell
taskkill /F /IM JU-v2.1-win-x64.exe
```

3. 重新启动。
   - **断言 A**：应用正常启动，无崩溃弹窗。
   - **断言 B**：至少 `P9-强杀前-ABC` 在（已落盘部分不丢）。
   - **断言 C**：`P9-强杀中-XYZ` 若丢失属可接受（未落盘），但**不得**导致整库损坏/空白。
4. 查看 `%LOCALAPPDATA%\com.ju.app\crash_dumps\` 是否有崩溃包（可选）。

**留证**：强杀命令输出 + 重启后界面截图。
**失败判定**：整库空白 / 启动崩溃 = Critical。

## P-10 双击关闭（ISSUE-107）

1. 在窗口顶部标题区**双击**。
   - **断言 A**：按设计语义执行（是关闭还是最大化，以 `tauri.conf.json` 配置为准）。
2. 若为关闭：重新启动，确认数据已在关闭前落盘。

**留证**：双击前后截图。
**说明**：这项要先确认「期望行为」，请以当前配置行为为准记录，不要以记忆判定。

2. 连续关闭/启动 5 次，改动内容。
3. **断言**：`backups/` 里保留 3 份，多出的被清理。

**留证**：设置截图 + `dir backups`。

## P-12 基准 P95（ISSUE-109）

1. 造一个 1000 节点的文档（可用导入功能批量）。
2. 用 Chrome DevTools（`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` 启动）录 Performance。
3. 记录：首屏渲染、滚动 1000 节点、切换视图（大纲↔导图）的 P95。

**断言**：滚动 P95 < 100ms、视图切换 < 500ms（按 `1.docs/benchmark-roadmap.md` 的阈值核对）。
**留证**：DevTools 截图 + 数值表。

## P-13 多标签并发写盘（ISSUE-110）

1. 启动实例 A，编辑文档。
2. 再启动实例 B（双击同一个 exe）。
   - **断言 A**：若为单实例设计，B 应弹「已在运行」并聚焦 A（不产生第二个窗口）。
   - **断言 B**：若允许多实例，两边交替编辑 3 轮，关闭后重开，数据不丢不乱。
3. 检查 `%APPDATA%\com.ju.app\` 下**没有**残留的 `ju_store.*.json.tmp`。

**留证**：任务管理器截图（进程数）+ 重启后数据截图。
**失败判定**：双开导致数据回退 = Critical。

## P-14 加密写盘失败注入（ISSUE-111）

**前置**：需测试构建（`cargo test` 里的 `SYNC_FAIL_HOOK`），或手工制造失败。

手工法：
1. 加密态下编辑内容。
2. 用管理员权限把 `%APPDATA%\com.ju.app` 设为「只读」（`icacls ... /deny`）。
3. 触发保存。
   - **断言 A**：弹出「加密保存失败：已保留加密兜底，请尽快导出数据」。
   - **断言 B**：**不得**清空已有的密文库（内存态不丢、磁盘态不毁）。
4. 恢复权限 → 再次保存 → 成功。

**留证**：toast 截图 + 失败前后 json 对比。
**失败判定**：失败时清空库 = Critical。

## P-15 关闭加密磁盘态（复核失败分支）（ISSUE-112）

1. 加密态下点「关闭加密」，输入密码确认。
2. **断言 A**：`ju_store.json` 里 `encStore` 已被删除，节点为明文。
3. **断言 B**：备份目录里保留至少一份**加密**备份（回滚锚点）。
4. 重启 → 无需密码即可打开，数据完整。

**留证**：json 前后对比（有/无 encStore）。
**失败判定**：关闭加密后数据丢失 = Critical。

---

## P-16 关闭加密窗口内 exe 级强杀（ISSUE-113）

1. 加密态下点「关闭加密」，在密码确认后的**写入窗口内**（约 1 秒内）执行：

```powershell
taskkill /F /IM JU-v2.1-win-x64.exe
```

2. 重启应用。
   - **断言 A**：要么是「完整加密态」（encStore 在、需密码），要么是「完整明文态」（encStore 无、无需密码）。
   - **断言 B**：**不得**出现「encStore 被删但明文没写进去」的空库。

**留证**：json 快照 + 重启后界面。
**失败判定**：出现空库 = Critical。
