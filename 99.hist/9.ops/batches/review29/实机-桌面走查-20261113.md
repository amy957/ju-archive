### P-13 多标签并发写盘 — 通过

**首次判定有误，已更正。** 初判依据是「进程数 = 2 且窗口标题不同（`JU 笔记` / `JU`）」，
据此认定单实例失效。复测时用 `EnumWindows` + `GetClassName` 区分窗口类名，结果：

```
21308 | class=Window Class | title=JU        ← 唯一应用窗口（Tauri/WebView2）
21308 | class=Tao Thread Event Target | title=   ← 内部事件窗口
30572 | class=#32770       | title=JU 笔记   ← 标准 Win32 对话框类（MessageBox）
```

`#32770` 是 `singleton::note("JU 笔记已在运行，已请求切换到已打开的窗口。")` 弹出的
**原生 MessageBox**，不是第二个文档窗口。

- **断言 A 成立** ✓：第二实例走 `Ok(None)` 分支 → 弹提示 + `SetEvent` 请求聚焦 → 退出；
  全程只有一个文档窗口（class `Window Class`）
- 进程计数会短暂为 2，是因为该 MessageBox 为模态、等待用户点确定，进程尚未退出
- **断言 B**：不适用（单实例设计成立）
- **断言 C** ✓：数据目录无 `ju_store.*.json.tmp` 残留
- 局限：「聚焦已有实例」的可见效果被模态提示框遮挡，未独立取证（需在提示框出现前抓前台句柄）

实测（1280×800，1020 节点）：

| 指标 | 实测 | 预算 | 判定 |
| --- | --- | --- | --- |
| 首屏 First Contentful Paint | **188 ms** | — | 记录 |

**结论**：可测的两项均达标（视图切换余量 4.8 倍）；滚动项待虚拟列表滚动入口明确后补测。

## 附录：P-08 / P-14 的可复制命令（需管理员）

### P-08 NSIS 安装 / 卸载

```powershell
# 1) 安装（静默，便于取证）
Start-Process -Wait 'D:\juqa\v2.1.0\JU_2.1.0_x64-setup.exe' -ArgumentList '/S'

# 2) 断言 A：安装目录存在主程序，版本 2.1.0
Get-ChildItem "$env:LOCALAPPDATA\Programs" -Recurse -Filter 'JU*.exe' |
  Select-Object FullName, @{n='Ver';e={$_.VersionInfo.FileVersion}}

# 3) 从开始菜单启动，确认无 WebView2 报错
Start-Process "$env:LOCALAPPDATA\Programs\JU\JU.exe"

# 4) 卸载（走 NSIS 卸载器，静默）
$u = Get-ChildItem "$env:LOCALAPPDATA\Programs\JU" -Filter '*uninstall*.exe' | Select-Object -First 1
if ($u) { Start-Process -Wait $u.FullName -ArgumentList '/S' }

# 5) 断言 B：程序目录应清空（允许残留卸载器自身）
Get-ChildItem "$env:LOCALAPPDATA\Programs\JU" -ErrorAction SilentlyContinue

# 6) 断言 C：用户数据必须保留
Test-Path "$env:APPDATA\com.ju.app\ju_store.json"   # 期望 True
```

### P-14 加密写盘失败注入

```powershell
# 1) 先在应用内开启加密并编辑内容，使数据处于加密态
# 2) 拒绝当前用户写入数据目录（注意：先备份，恢复命令在最后）
$d = "$env:APPDATA\com.ju.app"
icacls $d /deny "$env:USERNAME:(W)"

# 3) 回应用内触发保存 → 期望 toast：加密保存失败，已保留加密兜底
#    断言 A：出现该提示；断言 B：ju_store.json 内 encStore 仍在、未被清空
Get-Content "$d\ju_store.json" -Raw | Select-String 'encStore'

# 4) 恢复权限
icacls $d /remove:d "$env:USERNAME"
# 5) 再次保存应成功
```

> 两条命令都会改动系统状态，执行前请确认可回滚；P-14 的 `icacls /deny` 若忘记 `/remove:d`，
> 会造成应用持续无法写盘。

### P-12 基准 P95 的替代方案（若 CDP 仍不可用）

当前 `--remote-debugging-port` 端口 LISTENING 但 `/json/version` 超时，DevTools 性能面板无法接入。
可行替代：在应用内加一个只在 `JU_PERF_PROBE=1` 时启用的 `PerformanceObserver` 采集器，
把首屏渲染 / 滚动 1000 节点 / 视图切换的 P95 写入 `%APPDATA%\com.ju.app\perf.json`，
既绕开 CDP，又能进 CI 做阈值回归。
