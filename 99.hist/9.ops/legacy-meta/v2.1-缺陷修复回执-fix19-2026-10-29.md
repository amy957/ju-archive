### 必须显式声明的口径

1. **「选区保持不变」的真实判据是产品跨行模型，而非被引擎钳制的原生 `Selection`**：
   Blink（Edge / WebView2 同源）不允许原生 `Selection` 跨「编辑宿主」，原生选区恒被钳在首行单块内。
   因此本批以「产品模型 `covered` 仍 ≥2、overlay 多行高亮仍存在、模型锚点/焦点仍分处第 2/第 4 行」作为
   「多行选区未坍缩」的主判据；同时以 `xselCaptureNative()` 记录的原生可见子选区做逐字长度校验（11 == 11）。
2. **加粗的 DOM 落盘形态**：产品纯 DOM 引擎以 `font-weight:bold` 内联样式落盘，**不强制** `<b>/<strong>` 语义标签。
   故测试断言 1 同时接受「`<b>/<strong>` 标签」或「`font-weight:bold` 样式」——二者都是「加粗已生效」的真实 DOM 事实
   （与既有 `richtext-style-stack.spec.ts` 对 `font-weight ≥ 600` 的口径一致）。
3. **回滚点建立时机**：任务顺序为「先 build-all，再建 manifest」，而 build-all 会覆写 `release/JU-v2.1-Web.html`。
   为满足「`.bak-D19` 必须等于本批开工时发布版」，已在 build-all **之前**从当时的 `release/JU-v2.1-Web.html`
   原样复制出 `JU-v2.1-Web.html.bak-D19`（sha256 复核 = `8b0612…b233`），随后再 build-all。未改写任何历史哈希。

## 三、产品修复（P1）

### 3.1 `src/ui/xselect.ts`（新增两个导出，既有 API 一行未改）

```ts
export interface XSelNativeSnap { id: string; from: number; to: number; }

/** 记录原生选区在单宿主内的可见子选区（宿主 id + 纯文本偏移 from/to）。 */
export function xselCaptureNative(): XSelNativeSnap | null {
  const s = window.getSelection();
  if (!s || !s.rangeCount || s.isCollapsed) return null;
  const r = s.getRangeAt(0);
  const hs = closestHost(r.startContainer);
  const he = closestHost(r.endContainer);
  if (!hs || !he || hs !== he) return null;
  const id = String(hs.dataset.id || '');
  if (!id) return null;
  const a = offsetIn(hs, r.startContainer, r.startOffset);
  const b = offsetIn(he, r.endContainer, r.endOffset);
  return a <= b ? { id, from: a, to: b } : { id, from: b, to: a };
}

/** 格式命令写完后：保留跨行模型（不清空 _state / overlay），按快照还原原生选区并重绘。 */
export function xselKeepAfterFormat(snap?: XSelNativeSnap | null): void {
  if (!_state) return;
  const s = window.getSelection();
  let restored = false;
  if (snap && s) {
    const rg = xselRangeInHost(snap.id, snap.from, snap.to);
    if (rg) { try { s.removeAllRanges(); s.addRange(rg); restored = true; } catch (e) { /* ignore */ } }
  }
  if (!restored) xselRestoreNativeStart();
  paint();
}
```

- 纯文本长度在加粗后不变 ⇒ 以 (id, from, to) 偏移重建的 Range 与操作前逐字一致；
- `paint()` 复用既有 overlay 池，按新 DOM 几何重绘多行高亮；
- **不删除**模型（区别于 `xselClear()`），从根本上消除「收缩至第一行」。
