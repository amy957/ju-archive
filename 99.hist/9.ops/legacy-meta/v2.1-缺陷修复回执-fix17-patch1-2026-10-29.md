## 三、产品修复（P1）· `src/style.css` 仅追加

```css
/* ===== 【fix17-patch1 · 右栏内容缩进对齐】内容体左缘与分区标题「文字」左缘同列 =====
   取证（right_panel_indent_before.log / right_panel_indent_before17.log；1440×1000，Edge 真窗口 file://，
        fix17 发布版 ab64f774…460a 与 fix18 发布版 184de7df…d508 实测同值）：
     · 分区标题文字左缘 = 1244.2 = .sr-title padding-left 8 + chev 实测宽 10.2 + gap 6；
     · 其下内容左缘 = 1228（.sr-star-row / .sr-edit-row / .sr-btn 的 8px 内距）
       ⇒ 内容整体比标题文字左偏 16.2px；「链接 / 反链」正文（.bl-group-head padding 6 → 1226）偏 18.2px。
   本段只追加覆盖（既有规则一行未改）：
     ① .sr-body 统一左内距 = chev 宽 + 标题 gap ⇒ 内容首元素（锁图标 / 操作行图标 / 正文文字）
        与标题文字同一条竖线；元素自身原有 8px 内距保持不变，
        因此 fix17 的「锁 / 操作行图标同列」不变量仍成立（三列同步平移，列内极差仍 0）。
     ② 缩进量用 em 表达（.sr-title 字号 12px = .sr-section 15px 的 0.8em，chev .85em ⇒ 10.2px），
        不写死 px，随侧栏字体缩放同步变化。
     ③ 「链接 / 反链」正文由 JS 生成（.bl-group-head 6px / .bl-row 6px / .bl-hint 6px 内距），
        统一到 8px，使正文与标题文字严格同列。 */
#sidebarRight .sr-section{--rb-title-indent:calc(0.8em * 0.85 + 6px)} /* 实测 16.2px @15px 基准 */
#sidebarRight .sr-body{padding-left:var(--rb-title-indent);box-sizing:border-box}
#sidebarRight #srBacklinks .bl-group-head{padding-left:8px}
#sidebarRight #srBacklinks .bl-row{padding-left:8px}
#sidebarRight #srBacklinks .bl-hint{padding:2px 8px 6px}
#sidebarRight .sr-print-opt{padding-left:8px;padding-right:8px}
```

**为什么用 `--rb-title-indent` 而不是写死 20px**：缩进量等于「标题里 chev 的实测宽度 + 标题 gap」，
chev 宽度随字号变化（`.85em × .sr-title`），所以用 `calc(0.8em * 0.85 + 6px)` 表达，
在侧栏 15px 基准下解析为 `16.2px`，字体缩放时自动跟随；数值由探针实测反推，不靠推算凑数。

**未改动**：`index.html`（侧栏结构）、`src/ui/rightbar.ts`、`JU.ui()` 对象、`boot.ts`、富文本核 —— 零逻辑改动，纯 CSS 覆盖。
