## 二、P0：多标签 title 顺序断言（测试修正）

文件：[`tests/v21-fix2-cal-todo-tagchip.spec.ts`](../../6.P0-T3基线/m07-vite/tests/v21-fix2-cal-todo-tagchip.spec.ts:397)

* 修改前（fix2 遗留）：
  * 正向 `new RegExp('#' + first + '[\\s\\S]*#' + n.tags[1])`
  * 以及**反向顺序断言** `new RegExp('#' + n.tags[1] + '[\\s\\S]*#' + first)` —— 强求 title 同时满足两个方向的顺序，属自相矛盾的断言。
* 修改后：
  ```ts
  const title = await cb.getAttribute('title');
  expect(title, '多标签：title 必须包含第一个标签名').toContain('#' + first);
  expect(title, '多标签：title 必须包含第二个标签名').toContain('#' + n.tags[1]);
  ```
* 理由：`title` 由 `renderCalNode` 按 `_nodeTags` 插入顺序拼接（[`calendar.ts:2293`](../../6.P0-T3基线/m07-vite/src/views/calendar.ts:2293) `_nodeTags.map(t => '#' + t).join(' ')`），顺序由插入顺序决定，不应强求反向顺序；改为「两个标签名都在」的语义断言。
* 取证：`grep 反向核对` 全仓 0 命中；本次运行该 spec 5 条全 ok（`pw_full_fix3.log` 第 76~80 项区间内 `v21-fix2-cal-todo-tagchip` 5 条 ok）。
