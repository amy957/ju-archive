## 3. P1 修复（仅 `src/style.css`，零漂移）

### 3.1 块级层清零

```css
.text.ju-xsel{background-image:none!important;background-color:transparent!important;box-shadow:none!important;border-radius:0!important}
```

`.ju-xsel` 仍由 `src/ui/xselect.ts` 打标（跨行选区模型 / 工具栏逐块套样式 / 跨行删除继续依赖它），**只是不再参与绘制**。

### 3.2 行级层清零（作用域仅 `.outline`）

```css
.outline .row.sel,.outline .row.multi-sel{background:transparent!important;background-color:transparent!important;border:none!important;outline:none!important;box-shadow:none!important}
```

`:hover` 与 `:has(.text:focus)` 两个态同步清零（否则 `!important` 被更高特异性的态规则覆盖）。
**作用域限定 `.outline`**：侧边栏 / 日历行（`.row.sel` / `.cal-row.sel`）保持原样，未受影响。

### 3.3 原生选区统一为产品绿（`.text` 与 `.text.ju-xsel` 同色）

```css
.outline .text::selection{background-color:color-mix(in srgb,var(--accent) 20%,transparent)!important;color:inherit}
.outline .text.ju-xsel::selection{background-color:color-mix(in srgb,var(--accent) 20%,transparent)!important;color:inherit}
```

fix11 的 `.text.ju-xsel::selection{background-color:transparent}` 已被替换为**同色**——不再出现「块内透明 ⇒ 深一块浅一块」的双层观感。

### 3.4 光标

`caret-color:var(--accent)`（`src/style.css` 的 `.text` 规则）**未改动**；实测 `rgb(51,101,76)`、非透明。

## 7. BLOCKED / 残余（单列，不计入 PASS）

### 7.1 跨行可见高亮：BLOCKED（引擎钳制）

- 事实：Blink 把原生 `Selection` 钳在**单个 contenteditable 宿主**内。
  - 本批实测：竖向拖选 3 行 ⇒ `window.getSelection()` 仅 20 字符、**不含换行**、`nativeBlocksSpanned = 1`；
  - 历史对照：`90过程材料/tmp_compare/fix7/richtext_capability.log` → `RT_MULTILINE_CAPABILITY_VERDICT: SINGLE_HOST_CLAMPED`
    （编程式跨宿主 Range / 零监听克隆体 / 两个裸 contenteditable，三种对照 `covered=1`）。
- 影响：单层化后，竖向拖选时**原生绿色只可能覆盖第 1 个正文块**；第 2~3 块虽在选区模型内
  （`__juXsel.describe().covered = 3`，Backspace / 工具栏仍逐块生效），但**没有第二层视觉**。
- 为何不在本批解决：任务书 P1 明确「不能用行级或块级背景模拟高亮，必须使用浏览器原生 ::selection」，
  而原生 `::selection` 在单宿主钳制下无法跨块着色。真正可行的跨行可见方案是 **CSS Custom Highlight API（`::highlight(...)`）**，
  需在 `src/ui/xselect.ts` 侧注册 `Range` 并新增 `::highlight` 样式 —— 属改动选区核心，超出本批授权范围（本批禁止改 `xselect.ts`）。
- 结论：**BLOCKED（待后续批次）**，如需立即实现应单独开批次并在任务书中授权 `xselect.ts`。

### 7.2 焦点行底色消失（设计取舍，已在任务书范围内执行）

- 事实：`.row.sel` / `.row.multi-sel` 是**焦点行 / 节点多选标记**（`outline.ts:403/:1083`、`focus.ts:247-248`），
  清零后大纲视图内「当前焦点行」不再有整行底色（类名与逻辑仍在，只是不绘制）。
- 判断：这是达成「绿色区域 == 选区区域」的必要代价，且任务书 P1 明确要求移除这两类的背景色。
- 后续建议：若需恢复焦点提示，改用**非选区语义**（如行左侧 2px `--accent` 竖条 / 文本左侧细边），**不得**回退整行底色。
