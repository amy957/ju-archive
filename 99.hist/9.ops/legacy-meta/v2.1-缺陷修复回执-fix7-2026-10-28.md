### 2.2 根因（两处，互相独立）

1. **口径错**（`src/core/actions.ts` 旧 `updateText` → `logActivity('mod', id, null, diff)` →
   `charStats[ds].mod += cMod`）：`diff = stripHtml(new).length - stripHtml(old).length` 是**字符长度差**，
   于是新输入算「修改」、删除后为负值、替换既不加新增也不加删除。
2. **绑定错**（`src/main.ts` 的 `liveStateEarly`）：日历面板读 `deps.state.charStats`，
   而该 state 代理只代理了 `nodes / rootId / trashed / _tags`，`charStats` 落到普通属性（`undefined`）⇒
   **面板永远 0**，与 `state.charStats` 的真实值彻底脱钩。

## 3. P1 修复（按《精简完整方案》执行）

### 3.1 `src/core/wordcount.worker.ts` — 分词与 token 差分（新增，M5-2 协议零改动）

- `tokenize(text, opts)`（`wordcount.worker.ts:161`）：中日韩（含假名 / 谚文 / 汉字扩展 / 兼容区）按**字素簇** 1 token；
  非 CJK 字母数字连续串按**词** 1 token（`englishWords:false` 可退化为逐字符）；空白每字符 1 token；
  标点 / emoji / 符号每字素簇 1 token。字素簇优先 `Intl.Segmenter('zh', {granularity:'grapheme'})`，
  不可用回落 `Array.from`（码点）—— emoji（含 ZWJ 组合）恒按 1 个计。
- `countTokens`（`:185`）、`hashTokens`（`:190`，退出校准的块级摘要）。
- `tokenDiff(old, new)`（`:213`）：公共前缀 / 公共后缀剥离 + 中段**多重集匹配**，
  `I = |midNew| - matched`、`D = |midOld| - matched`，再按 `M=min(I,D)`、`A=I-M`、`R=D-M`、`N=I-D` 出四象限。
  复杂度 O(n+m)，**不做** O(n·m) 的 LCS（大文档不阻塞主线程）。
- Worker 协议扩展：`{type:'tokenDiff', rid, oldText, newText}` → 回 `{type:'tokenDiff', rid, I, D, A, R, M, N}`；
  **M5-2 的 `{nodes, docId}` → `{docId, wordCount}` 分支逐字保留**（`store.docWordCount` 路径零漂移）。

### 3.2 `src/core/charstats.ts` — 新增统计引擎

- 四象限落库：`applyDiff(s, ds, I, D)` 把 `A/R/M` 累加进 `charStats[ds].{add,del,mod}`，`net += N`，
  并 `charStatsRev++`（供面板/诊断判定刷新）。
- 运行中增量：`queueEdit(id, oldHtml, newHtml)`（`:180`）→ **500ms 批次合并**（同节点多次编辑只留「首→尾」）
  → `flushPending()`（`:222`）做一次 `tokenDiff`；节点新增/删除走 `queueNodeAdd`（`:189`）/
  `queueNodeRemove`（`:200`），整段 token 计入 A/R。
- 退出校准（快照 Diff）：当日基线 `state.charBaseline[ds][nodeId] = 首次触碰前 token 数`；
  `calibrate()`（`:263`）对全部基线节点比较当前 token，汇总 I/D 后**覆盖**当日桶（`setBucket`，绝不累加），
  并清除 `pendingCalibration`；`runStartupCalibrationIfPending()`（`:297`）在启动时优先执行；
  `flushOnExit()`（`:309`）在 pagehide / beforeunload 结算批次，来不及则置 `pendingCalibration` 交给下次启动。
- 持久化与节流：统计改动统一走 `commit(..., {silent, light})` → `scheduleNotify` → `schedulePersist`
  （300ms 写合并，**不逐键写盘**）；面板重绘另设 1s 节流门限 `uiTick()`（`:133-139`）。
- 大文本：纯文本超过 `threshold`（默认 20,000 字符）改走**独立**内联 Worker 做差分，失败回落主线程同步。

### 3.3 `src/core/actions.ts` — 只发「编辑前后 HTML」，不再发长度差

- `ActionsDeps` 新增 3 个可选端口：`charStatsEdit / charStatsNodeAdd / charStatsNodeRemove`（`:113-124`）。
- `updateText`（`:264-277`）：commit 后调用 `deps.charStatsEdit(id, 旧 HTML, 新 HTML)`（try/catch）；
  `logActivity('mod', id, null, null)` 不再传长度差。
- `logActivity`（`:603-630`）：commit 内**移除** charStats 累加（只维护 `activity` 120/天、90 天、5000 条上限流水）；
  commit 之后仅对 `add` / `del` 两个「整节点事件」调用引擎 —— 避免与 `updateText` 的 token 增量双重计账。

### 3.4 `src/main.ts` — 活引用 + 装配 + 退出校准

- `liveStateEarly` 补 4 个 getter（`:760-763`）：`charStats / charBaseline / charStatsRev / pendingCalibration`
  —— **面板恒 0 的根因修复**（读活引用而非模块初始化时的空快照）。
- `injectActionsDeps` 注入 3 个端口（`:1235-1237`）→ `core/charstats`。
- `start()` 之后装配引擎（`:2187-2202`）：`injectCharStatsDeps({getState, commit, scheduleNotify, schedulePersist})`
  → `runStartupCalibrationIfPending()` → `pagehide` / `beforeunload` → `flushOnExit()`；
  `visibilitychange(hidden)` → `flushPending()`。

### 3.5 `src/views/calendar.ts` — 净变化口径

- `calModuleCharsBody` 新增 `netOfBucket(b)`（`:1347`）：优先 `b.net`，缺失（历史数据）回落 `add - del`，
  **绝不**回落 `add - del + mod`；`totalNet` / 年视图 `monthNet` / 周月视图 `dayNet` 三处统一走它。
- 面板刷新沿用既有渲染链：切回日历走 `renderCalendarPage` 重建模块；日历视图内编辑走
  `src/app/render.ts:241-242` 的 `data-key="chars"` 局部重填（不重建 `#content`、不丢焦点）。

## 8. BLOCKED / 遗留（单列，不以 PASS 冒充）

- **BLOCKED：无。**
- 说明性备注（非缺陷、非阻塞）：
  1. 窗口尺寸/字号无关：本批为纯统计口径与数据绑定修复，未改任何 CSS。
  2. `charStats` 旧数据（历史 `{add,del,mod}` 无 `net`）在面板上按 `add - del` 回算净变化，
     不再使用 `add - del + mod`；引擎首次写入即补上 `net` 字段，属向后兼容而非迁移脚本。
  3. 校准对「当日基线」求和后**覆盖**当日桶（任务书要求「绝不能用累加」）；因此同一内容在
     「刷新前（增量口径的逐步累计）」与「刷新后（校准覆盖）」可能呈现不同 A/R/M 拆分，但
     `net`（净变化）一致且 `add - del == net` 恒成立 —— 探针与 spec 均按此断言。
