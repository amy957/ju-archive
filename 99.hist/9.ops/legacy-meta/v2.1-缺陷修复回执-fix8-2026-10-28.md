### 3.1 过程中被自家 spec 抓到的 CSS 缺陷（诚实记录，已纠正）

首版实现用的是「列 `border-right` + `:last-child{border-right:none}`」写法。新增 spec 第 1 条**直接判红**：

```
Error: 最右列不得再画右边框（由 .cal-module 外框收边）  Expected: 0  Received: 1
```

根因：列容器 `.cal-tg-cols` 尾部还追加了 `.cal-tg-nowline` / 时间线等兄弟节点，**`:last-child` 永不命中列**。
改为「`border-left` + `:first-child{border-left:none}`」模型后不再依赖「谁是最后一个孩子」，3 条 spec 全绿。
（留痕口径：`90过程材料/tmp/fix8/pw_new_spec_fix8.log` 保存的是**最终绿态**；红态即为本节上方逐字引用的 Playwright 断言消息
`最右列不得再画右边框（由 .cal-module 外框收边） Expected: 0 / Received: 1`，此处如实记录而不覆盖为「一次通过」。）

## 4. P2 修复 —— 面板拉高时的空白（`src/style.css`）

| 行号（修复后） | 规则 | 改动 |
| --- | --- | --- |
| 385 | `.cal-tg-scroll` | `max-height:min(8h,60vh)` **删除 → `max-height:none`**；`flex:1 1 auto` → **`flex:1 1 0`**（basis 0：只吃剩余高度，**不按 24h 内容反撑高模块**）；`min-height:min(8h,60vh)` **保留**（初始仍见 8 小时）；`overflow-y:auto` |
| 453 | `.cal-module[data-key="calendar"]>.cal-module-body` | **新增** `display:flex;flex-direction:column`（原仅 `padding:0`） |
| 347 | `.cal-top` | **新增** `display:flex;flex-direction:column;flex:1 1 auto;min-height:0` |
| 384 | `.cal-tg` | **新增** `flex:1 1 auto;height:100%;min-height:0` |

形成 `.cal-module-body → .cal-top → .cal-tg → .cal-tg-scroll` 的**竖向 flex 链**：网格区吃掉模块剩余高度，
24 小时内容由滚动条承载（行高固定，不做「按总高均分」以免事件块与拖拽吸附口径漂移）。
底色（`var(--bg-panel)`）由 `.cal-tg` 满铺整个网格容器，不截断。

> 设计口径说明：任务书给了两条可选路径（「行高按总高均分」or「固定行高 + 滚动容器 100% + overflow-y:auto」）。
> 本批选后者 —— 原因：`.cal-tg-ev` 事件块的 `top/height`、拖拽吸附、`tgTimeY()` 全部以 `--tg-hour-h` 为唯一物理量，
> 均分行高会让「同一待办在 8h 视口与 24h 视口里对应不同像素高度」，属于功能性口径漂移；滚动方案则保持零漂移。

### 4.1 中途回归与自纠（诚实记录）

第一版 `.cal-tg-scroll{flex:1 1 auto}` 时，basis `auto` 取内容高（1098px）→ **模块被撑到 1207px、24 小时全铺开、无滚动条**。
探针 after 阶段当即测出（`cal_mod` 1207 / `scroll clientH` 1095），且「拖拽拉高」因把手已在视口外而**实测未增长**，
探针据自身规则判为「未取证」而非 PASS。改为 `flex:1 1 0` + 保留 8h `min-height` 后复测通过，且探针新增
「分段拖拽 + 只认实测增长 + 增长不足即记 `BLOCKED_KIND: EVIDENCE`」三条硬闸门，避免把无效拖拽当 PASS。
