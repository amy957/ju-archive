## 一、动因与范围

- **动因**：Defect-J 属 P0 级内存增长缺陷 —— 每秒 1 次删除的常规使用下，`_tombstoneQueue` 以 1 条/秒线性增长（12,000 次删除 ⇒ 12,000 条，旧口径实测；外推 8 小时挂机 ≈ 28,800 条）。
- **范围**：仅 [`canonical`](../../6.P0-L3基线/v2.0-l3.html.html:1) + step9 镜像 + 登记 / 门禁口径 + N 层用例 / 证据 / 波报告；**不新增纳编物**（登记方数保持 **43**）。

### 5.1 N 层回归（新增 · 11/11 通过）

`node --test l9/l16-w11-tombstone-queue-compaction.test.mjs` ⇒ `# tests 11 / # pass 11 / # fail 0`（证据 [`_l16w11-ntest-2026-10-17.txt`](_l16w11-ntest-2026-10-17.txt:1)）：

- **A 结构锚点**：`const TOMB_QUEUE_MAX=4096;` 存在；`_tombstoneSet` 内有 `_tombstoneCompactQueue();` 调用；compaction 体内含 `_recentlyRemoved.has(k)` / `q.length=_w` / `_tombstoneFifoHead=0` / `q.length<=TOMB_QUEUE_MAX`；容量触发 `if(_recentlyRemoved.size>2000){` 保留且含「队首仍有未判定条目」门控。
- **B 缺陷复现（旧口径）**：12,000 次稀疏删除后队列 **= 12,000**（逐条累积，无 compaction）。
- **C 验收（新口径）**：3,600 次稀疏删除（1 次/秒 · 虚拟时钟）后 **队列 = 3,600（峰值 3,600 ≤ 8192）**、`_recentlyRemoved` 峰值 **230 / 终态 31 ≤ 2000**；同序列旧口径对照恒为 3,600（判别力真实）。
- **D 突发 5,000 次删除**：`_recentlyRemoved` = **2,000（容量上界）**、队列 **903 < 5,000**（compaction 生效）、队列条目严格按写入序（无空洞 / 无重复）。
- **E compaction 正确性**：3,000 条过期 + 2,000 条新鲜 ⇒ 队列中**零条已过期条目**、游标归零、存活条目顺序保持。
- **F initStore 复位**：复位后队列 0 / 游标 0，再写入队列 1 且滚动游标为 0；空队列 compaction 幂等（零副作用）。
- **G 大 state（50,000 节点）P95**：单次墓碑写入 **P95 0.0010ms（预算 0.5ms）**、P99 0.0036ms、max 0.2670ms（compaction 单次抖动）；队列 2,031 ≤ 8192、Map 31 ≤ 2000。
