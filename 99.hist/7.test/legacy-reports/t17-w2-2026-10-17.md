- **缺陷定位（Defect-P0-2 · 实测复核）**：改前 [`renderCalendarPage()`](../../6.P0-L3基线/v2.0-l3.html.html:9496) 的 week 分支为

  ```js
  }else if(calView==='week'){
    const sel=parseYmd(ui.selectedDate||todayStr());
    const selY=sel.getUTCFullYear(),selM=sel.getUTCMonth(),selD=sel.getUTCDate();
    const dow=new Date(Date.UTC(selY,selM,selD)).getUTCDay();
    const days=[];
    for(let i=0;i<7;i++)days.push(new Date(selY,selM,selD-dow+i));
  ```

  而同一函数的 month / year 分支、`ymd()`、`buildTimeGrid()`、`parseYmd()`（**FIX-TZ-1** 起显式改为 `new Date(y,mo-1,d)` 本地构造）**一律使用本地日历语义**。东八区（UTC+8）本地零点 = 前一日 16:00Z ⇒ **UTC 日期恒比本地日期早一天**，UTC 星期 = 本地星期 − 1（模 7）：

| 选中日 | 本地 dow | UTC 取值器得 dow | 起始日 | 结论 |
|---|---|---|---|---|
| 周一 ~ 周六 | 1..6 | 0..5 | `(selD-1)-(dow-1)` | 两项恰好抵消 ⇒ **巧合正确** |
| **周日** | **0** | **6** | **`(selD-1)-6` = 选中日 − 7** | **整周回退一周**（列头星期 / 时段条带 / 当天高亮全部错位） |

> **实测复现（东八区 · 只读冻结锚 frozen-l14 驱动）**：选中 `2026-10-18`（周日）⇒ 周区间为 `2026-10-11 ~ 2026-10-17`（**选中日不在周内**）；选中 `2026-11-01`（周日）⇒ `2026-10-25 ~ 2026-10-31`。
> **为何既有门禁未拦截**：Node 145 / PW 171 / bench 7 均未断言「周视图周区间与选中日的星期对齐」；且缺陷仅在**正偏移时区 + 周日**组合下显形，CI 参考机与用例均未覆盖该组合。本波以 N 层用例（固定 `TZ=Asia/Shanghai`）直接装配 week 分支并以只读冻结锚复现红证（§五）。

## 二、实现

### 2.1 取值器口径统一为本地日历

```js
/* L17-W2 · 指令 2（Defect-P0-2）：原以 getUTCFullYear/getUTCMonth/getUTCDate + Date.UTC 求星期，
   而 parseYmd()（FIX-TZ-1）/ ymd() / buildTimeGrid() 一律为本地日历语义；东八区本地零点 = 前一日 16:00Z
   ⇒ UTC 日期恒早一天、UTC 星期 = 本地星期 − 1（模 7）：周一至周六两项恰好抵消，周日（本地 dow=0、
   UTC dow=6）起始日 = 选中日 − 7，整周回退一周。改为本地取值器 + 本地基准日，周序列口径不变。 */
const selY=sel.getFullYear(),selM=sel.getMonth(),selD=sel.getDate();
const dow=new Date(selY,selM,selD).getDay();
const days=[];
for(let i=0;i<7;i++)days.push(new Date(selY,selM,selD-dow+i));
top.appendChild(buildTimeGrid(days));
```

### 2.2 收口对照

| 接缝 | 改前 | 改后 |
|---|---|---|
| 年 / 月 / 日取值 | `getUTCFullYear/getUTCMonth/getUTCDate` | `getFullYear/getMonth/getDate`（本地） |
| 星期基准 | `new Date(Date.UTC(...)).getUTCDay()` | `new Date(selY,selM,selD).getDay()`（本地基准日） |
| 周序列 | `new Date(selY,selM,selD-dow+i)`（7 日 · 周日起） | **逐字保留** |
| 选中日解析 | `parseYmd(ui.selectedDate\|\|todayStr())` | **逐字保留** |
| 渲染收口 | `top.appendChild(buildTimeGrid(days))` | **逐字保留** |
| month / year 分支 | 本地语义 | **未触碰** |

> **决策记录 L17-W2-D1（取值器口径统一为本地日历，不做「周日 +7」特判）**：缺陷根因是**取值器口径混用**（本地构造 + UTC 取值）。若仅在 `dow` 上补 `+7`，周一起点 / 跨月 / 跨年边界仍会在负时区或 DST 时区出现隐性错位；故与 FIX-TZ-1 的既有约定对齐——**构造、取值、比较一律本地**。
> **决策记录 L17-W2-D2（周序列与列头口径零变更）**：`days` 仍为「周日起 7 日」且直接交由 `buildTimeGrid(days)`；后者列头星期取自 `d.getDay()`（本就本地），故只需修正起始日即可整体对齐，无需改动下游。
> **降级 / 契约**：`state.nodes` 结构、`juju.store.v31` 序列化形状、加密 payload 字段名**零变更**；公开 API（`window.__juIndexShadow` / `__juPersistProbe` / `__juL9Shadow` / `__juL10D1`）零变更；本分支不涉及 `__l14On()` / `_vsUserDisabled` / `IS_DESKTOP` 开关；**不新增 `<script>` 块**（9 块 · 静态语法全通过）。
> **注释保全**：仅新增 4 行 L17-W2 说明注释；既有 `FIX-TZ-1` / `FIX-P0-1` / `FIX-L-15` 等历史编号注释**零清理**。
