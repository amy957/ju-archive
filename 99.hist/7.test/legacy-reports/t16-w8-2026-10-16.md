## 一、动因与范围

- **动因**：落实《优化指令 · 指令 8》。`_tombstoneSet` 是硬删除 / 回收 / purge 统一墓碑写入路径（`removeNodeFromMap` / `moveToTrash` / `purgeTrash`）；在「30s 窗口内高速删除 2000+」场景下，旧实现的超容量分支**每次写入都触发一次 O(2000) 全表过期扫描**，形成周期性毛刺。目标：把「一次性 O(n) 全扫」切分为**固定批量惰性分段**，均摊代价降为 O(batch)。
- **范围**：仅 [`canonical`](../../6.P0-L3基线/v2.0-l3.html.html:1) + step9 镜像 + 登记 / 门禁口径 + 波报告 / 证据；**不新增纳编物**（登记方数保持 **43**）。

## 二、实现（惰性分段清扫）

### 2.1 改前口径（旧 · 超容量分支）

```js
if(_recentlyRemoved.size>2000){
  for(const[k,v]of _recentlyRemoved){if(_now-v>30000)_tombstoneDelete(k,target);}  /* ← 每次写入 O(n) 全表扫描 */
  while(_recentlyRemoved.size>2000){
    const k=_recentlyRemoved.keys().next().value;
    if(k===undefined)break;
    _tombstoneDelete(k,target);
  }
}
```

### 2.2 改后口径（本波 · 队首游标惰性分段）

```js
let _tombstoneQueue=[];        /* 插入顺序 id 数组 */
let _tombstoneFifoHead=0;      /* 队首游标（O(1) 前向推进） */
const TOMB_SWEEP_BATCH=32;     /* 单次推进的最大条目数 */

/* _tombstoneSet 内：写入时登记插入顺序 */
_recentlyRemoved.set(id,_now);
_tombstoneQueue.push(id);

/* 容量触发：从队首惰性推进固定批量，每条做一次过期判定 */
if(_recentlyRemoved.size>2000){
  let _batch=TOMB_SWEEP_BATCH;
  while(_batch>0&&_tombstoneFifoHead<_tombstoneQueue.length){
    const k=_tombstoneQueue[_tombstoneFifoHead++];
    _batch--;
    if(k===undefined)continue;
    const v=_recentlyRemoved.get(k);
    if(v===undefined)continue;                 /* 已被计数清扫 / FIFO 收缩移除 —— 跳过陈旧条目 */
    if(_now-v>30000)_tombstoneDelete(k,target);
  }
  while(_recentlyRemoved.size>2000){            /* FIFO 上界：Map 首键 O(1) 收缩（≤2000） */
    const k=_recentlyRemoved.keys().next().value;
    if(k===undefined)break;
    _tombstoneDelete(k,target);
  }
  if(_tombstoneFifoHead>4096){_tombstoneQueue=_tombstoneQueue.slice(_tombstoneFifoHead);_tombstoneFifoHead=0;}  /* 游标压缩防无界 */
}
/* 保留：if((++_tombstoneOps)%200===0){ 全表轻量清扫 } —— 兜底 */
```

| 接缝 | 改前 | 改后 |
|---|---|---|
| 超容量过期清扫 | **O(n) 全表扫描**（每次超容量触发） | **O(batch=32) 队首惰性分段**（游标前移） |
| FIFO 上界 | `while(size>2000)` 删最旧（O(1)/条） | **不变**（Map 首键 O(1) 收缩） |
| 队列登记 | 无 | 写入时 `_tombstoneQueue.push(id)`；`mergeRemoteState` 并入 / `initStore` 恢复同步 push |
| 稀疏删除兜底 | `%200` 全量清扫 | **保留**（`%200` 全量清扫） |
| 容量上界 | ≤2000 | **≤2000**（不变） |
| 单次代价 | O(n)（n≈2000） | **O(batch=32)** |

> **降级 / 契约**：`_tombstoneQueue` / `_tombstoneFifoHead` / `TOMB_SWEEP_BATCH` 均为**模块级内存态**，不进 `state.nodes`、不改 `juju.store.v31` 序列化形状、不改加密 payload 字段名；`state._tombstones`（跨会话持久化墓碑）增 / 删语义不变。公开 API（`window.__juIndexShadow` / `window.__juPersistProbe` / `window.__juL9Shadow` / `window.__juL10D1`）方法名与返回形状**零变更**；**不新增 `<script>` 块**（9 块不变）。`_tombstoneSet` **不处于** `__l14On()` / `_vsUserDisabled` / `IS_DESKTOP` 门控之下 ⇒ 非优化分支行为不变。
