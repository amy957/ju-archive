## 一、动因与范围

- **动因**：加密态的设计前提是「敏感内容不落明文日志」；`msg` / `reason` 已占位，但 `stack`（含错误原文与源码片段）、`filename`（含本机用户目录绝对路径）、`lineno`（与 filename 组合可还原出错位置）仍明文进入错误环形缓冲、桌面错误日志文件与（显式配置端点时的）上报载荷，构成隐私保护缺口。
- **范围**：仅 [`canonical`](../../6.P0-L3基线/v2.0-l3.html.html:1) + step9 镜像 + 登记 / 门禁口径 + N 层用例 / 证据 / 波报告；**不新增纳编物**（登记方数保持 **43**）。

## 二、实现

| 接缝 | 改前 | 改后 |
|---|---|---|
| `msg` / `reason`（加密） | `<enc-message>` 占位 | **原样保留**（顺序不变） |
| `stack`（加密） | 错误原文（截断 4KB） | **`'<enc-stack>'`**（先于 4KB 截断，故超长 stack 亦为短占位） |
| `filename`（加密） | 本机绝对路径 | **`'<enc-filename>'`** |
| `lineno`（加密） | 行号 | **`'<enc-lineno>'`** |
| `ctx` 构造 | 内联三元式 `ctx:encNow?{…}:{…}` 直接嵌入 entry | **上提为 `const _ctx=encNow?{…}:{…}`**，`entry` 以 `ctx:_ctx` 引用（显式同源 · 加密 `enc:true` + `view/docId/nodeCount` 清零；非加密 `enc:false` + 常规上下文提取） |
| 非加密分支 | `msg` / `reason` 走 `_redactErrText`；`stack` 原样 + 4KB 截断 | **零变更**（降级分支逐字保留） |

改动后代码（canonical 现行 15975–16036）：

```js
    const encNow=(typeof ui!=='undefined'&&!!ui.encrypted);
    const _p={...payload};
    if(encNow){
      if(_p.msg!=null)_p.msg='<enc-message>';
      if(_p.reason!=null)_p.reason='<enc-message>';
      /* L16-W19 · 指令 10（Defect-I）：stack 携带错误原文与源码片段、filename 携带本机绝对路径、
         lineno 与 filename 组合可还原出错位置，加密模式下与 msg / reason 一并占位；非加密分支保持原样。 */
      if(_p.stack!=null)_p.stack='<enc-stack>';
      if(_p.filename!=null)_p.filename='<enc-filename>';
      if(_p.lineno!=null)_p.lineno='<enc-lineno>';
    }else{
      if(_p.msg!=null)_p.msg=_redactErrText(_p.msg);
      if(_p.reason!=null)_p.reason=_redactErrText(_p.reason);
    }
    /* … 去重 / 限流（逐字不变）… */
    const _ctx=encNow?{
      view:null,docId:null,nodeCount:0,enc:true,
      ver:(typeof JU_VER!=='undefined'?JU_VER:'fixed23')
    }:{
      view:(typeof ui!=='undefined'&&ui)?ui.view:null,
      docId:(typeof ui!=='undefined'&&ui)?ui.currentDocId:null,
      nodeCount:(typeof state!=='undefined'&&state&&state.nodes)?Object.keys(state.nodes).length:0,
      enc:false,
      ver:(typeof JU_VER!=='undefined'?JU_VER:'fixed23')
    };
    const entry={kind,ts:now,reported:false,ctx:_ctx,..._p};
```

> **决策记录 L16-W19-D1（占位边界与 ctx 绑定口径）**：① 加密分支占位集合界定为「用户内容 + 运行环境身份」两类 —— `msg` / `reason` / `stack`（用户内容与源码片段）+ `filename` / `lineno`（本机路径与位置），**`kind` / `name` 等结构字段保留**以保证错误可归类、可去重、可统计；② `stack` 占位**先于**原有 4KB 截断执行，故加密态 `entry.stack` 恒为短占位（不再可能保留 4KB 原文）；③ `ctx` 上提为 `_ctx` 并保持三元式两分支中 `enc` 与 `encNow` 一一对应，`entry` 以 `ctx:_ctx` 引用，避免内联三元式在后续改动中被误改。
> **降级 / 契约**：`state.nodes` 结构、`juju.store.v31` 序列化形状、加密 payload 字段名零变更；公开 API（`window.__juIndexShadow` / `window.__juPersistProbe` / `window.__juL9Shadow` / `window.__juL10D1`）零变更；`__l14On()` / `_vsUserDisabled` / `IS_DESKTOP` 相关分支不涉及（本函数无优化开关）；非加密分支（`ui.encrypted=false` 的常规运行路径）逐字不变；**不新增 `<script>` 块**（9 块 · 语法检查全通过）。
> **去重键说明**：`_errSeen` 键仍由 `payload.msg / filename / lineno` 原始值拼接 —— 该 Map 为模块内私有内存结构，**不进入 `__juLog`、不落盘、不上报**；加密态去重仍以原始 filename/lineno 提升判别力（登记 **OP-L16W19-1** 观察项）。
