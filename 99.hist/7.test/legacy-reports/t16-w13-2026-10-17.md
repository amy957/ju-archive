- **本波口径（Defect-F）**：对端节点 A→B 合入时 B 侧 `_origin='remote'`；B 从未写盘（`_diskConfirmed` 不含该 id，或该集合为 `null`）；A 删除后广播，B 收到不含该 id 的新快照 →

  实测成因叠加：`FIX-ORIGIN-2`（对端 `_localCreated` 并入本地）把 **A 的新建标记搬到 B**，使 `_localCreated` 守卫进一步永久挡住该 id 的删除传播。

## 一、动因与范围

- **动因**：Defect-F 属多标签一致性缺陷 —— 删除指令在接收侧被「未上盘」兜底静默吞掉，两端 `nodes` 数量长期分叉（且写盘后固化）。
- **范围**：仅 [`canonical`](../../6.P0-L3基线/v2.0-l3.html.html:1) + step9 镜像 + 登记 / 门禁口径 + N 层用例 / 证据 / 波报告；**不新增纳编物**（登记方数保持 **43**）。

## 二、实现（`state._remoteReceived` 对端合入保护集）

| 接缝 | 改前 | 改后 |
|---|---|---|
| 新字段 | 无 | `state._remoteReceived`（字符串 id 数组）：**由对端快照送入、且本页尚未写盘确认**的节点 id 集合 |
| [`defaultState`](../../6.P0-L3基线/v2.0-l3.html.html:4984) | `_localCreated:[]` | `_localCreated:[],_remoteReceived:[]` |
| [`migrateStateObject`](../../6.P0-L3基线/v2.0-l3.html.html:18654) | 仅归一化 `_localCreated` | 增 `_remoteReceived` 归一化（`typeof id==='string' && st.nodes[id] && 去重`，缺省 `[]`） |
| [`initStore`](../../6.P0-L3基线/v2.0-l3.html.html:2152) | 仅归一化 `_localCreated` | 同口径归一化 `_remoteReceived`（**跨刷新保留**） |
| [`mergeRemoteState`](../../6.P0-L3基线/v2.0-l3.html.html:1643) 插入分支（`rn._origin='remote';` 之后） | 仅标记 `_origin` | **登记 id** 至 `_remoteReceived`，并**同址从 `_localCreated` 摘除**（对端已送达 ⇒ 不再属「本页新建」） |
| `mergeRemoteState` 合入前归一化（节点循环之前） | 无 | ① 已不在本地节点表 → 摘除；② 对端新快照再次包含该 id **且** `_diskConfirmed` 命中（已上盘，保护已无必要）→ 摘除 |
| 删除传播守卫（`_localCreated` 守卫之后、`_diskConfirmed` 守卫处） | `if(!_diskConfirmed||!_diskConfirmed.has(id))continue;` | **保留**原守卫文本，改为门控块：`_remoteReceived` 命中时**放行删除**（不再以「未上盘」跳过） |
| `FIX-ORIGIN-2`（对端 `_localCreated` 并入本地） | 无差别并入 | **跳过** `_remoteReceived` 内的 id（该节点由对端送达，对端必然持有；回填会让 `_localCreated` 守卫永久阻挡删除） |
| 删除路径 | `removeNodeFromMap` / `purgeTrash` 仅清 `_localCreated` | 同址摘除 `_remoteReceived`（集合随删除收缩，无界风险消除） |
| 比对口径 | `_strip` 剥离 `_rev/_origin/_localCreated/_tombstones` | 追加剥离 `_remoteReceived`（两处：`mergeRemoteIfNewer` 与 `recoverPendingEncrypted`）——保护集变化非用户可见，不触发重渲染 |
| 持久化口径 | `_ORIGIN_STRIP` 仅剥离 `_origin` | **不变**（`_remoteReceived` 为持久化辅助字段，随快照原样写入；与 `_localCreated` / `_tombstones` 同口径） |
| 明文兜底 | `_pendingPlainState` 携带 `_localCreated` / `_tombstones` | 追加携带 `_remoteReceived`（崩溃恢复后删除传播判定不丢失） |

> **决策记录 L16-W13-D1（守卫极性）**：指令草案给出的守卫形状为「命中 `_remoteReceived` 即 `continue`（跳过删除）」，与验收目标（删除**必须**传播）互斥、且对 Defect-F 无效。本波按目标语义实现**等价反向门控**（仅命中时放行删除），落点仍位于 `_localCreated` 守卫之后的 `_diskConfirmed` 守卫处；同时补齐「登记即摘除 `_localCreated`」「继承跳过」两处成因修复，否则 `_localCreated` 守卫会在 `_remoteReceived` 判定之前先行 `continue`（§〇 ②，实测复现见 §5.1）。
> **降级 / 契约**：`_remoteReceived` 为顶层辅助数组（与 `_localCreated` / `_tombstones` 同级），**不改 `state.nodes` 结构 / `juju.store.v31` 节点形状 / 加密 payload 字段名**；`_ORIGIN_STRIP` 语义不变（仍只剥离 `_origin`）；非优化分支（`__l14On()=false` / `_vsUserDisabled=true` / `IS_DESKTOP=false`）行为不变；公开 API（`window.__juIndexShadow` / `window.__juPersistProbe` / `window.__juL9Shadow` / `window.__juL10D1`）零变更；**不新增 `<script>` 块**（9 块不变）。
