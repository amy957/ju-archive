## 一、动因与范围

- **动因**：异常路径的侧栏计数与真实 state 不一致 —— 星标数、文档数、数据库条目数在 patch 序列化失败或 light 提交后停留在旧值，直到下一次整体重建（`initStore` / `mergeRemoteState`）才纠正；期间 `renderSidebar` 以 O(1) 读取到错误计数。
- **范围**：仅 [`canonical`](../../6.P0-L3基线/v2.0-l3.html.html:1) + step9 镜像 + 登记 / 门禁口径 + N 层用例 / 证据 / 波报告；**不新增纳编物**（登记方数保持 **43**）。

## 二、实现（单点改动 · 保留 try/catch 兜底）

| 接缝 | 改前 | 改后 |
|---|---|---|
| [`commit()` 侧栏计数收口](../../6.P0-L3基线/v2.0-l3.html.html:4576) | `if(__juInMerge){重建} else if(_scBase){ if(patch有路径){增量} else {**继承旧基数**} } else {重建}` | `if(__juInMerge){重建} else if(_scBase&&patch有路径){增量} else {**全量重建**} ` |

改动后分支（canonical 现行 4576–4585）：

```js
  try{
    const _scBase=_sideCountsGet(_oldState);
    if(__juInMerge){
      _sideCountsSet(state,_sideCountsRebuild(state)); /* merge 期 state 就地改写 → 整体重建兜底 */
    }else if(_scBase&&_l8Patch&&_l8Patch.paths&&_l8Patch.paths.length){
      _sideCountsSet(state,_sideCountsApply(_scBase,_oldState,state,extractChangedIds(_l8Patch.paths,_l8Patch.meta)));
    }else{
      _sideCountsSet(state,_sideCountsRebuild(state)); /* 异常路径（patch 缺失 / 无基数）：全量重建，不再继承旧计数 */
    }
  }catch(_e){try{_sideCountsSet(state,_sideCountsRebuild(state));}catch(_e2){}}
```

> **决策记录 L16-W15-D1（异常路径取整体重建）**：patch 缺失 **不能** 作为「节点未变」的充分条件。`_sideCountsRebuild(state)` 为单次遍历（`for..in state.nodes` + 与 `renderSidebar` 原全表循环逐字对齐的贡献表达式），不分配中间结构（无数组 / Map / 对象池），异常路径罕见（patch 序列化失败 / light 提交），以其换取计数绝对正确。
> **降级 / 契约**：`_sideCounts` 仍以 Symbol 键挂载于 state（序列化 / patch 差集不可见）⇒ `state.nodes` 结构、`juju.store.v31` 序列化形状、加密 payload 字段名零变更；公开 API（`window.__juIndexShadow` / `window.__juPersistProbe` / `window.__juL9Shadow` / `window.__juL10D1`）零变更；`__l14On()=false` / `_vsUserDisabled=true` / `IS_DESKTOP=false` 行为不变；**不新增 `<script>` 块**（9 块不变）。
