## 一、动因与范围

- **动因**：落实《优化指令 · 指令 2》。`renderCalendarPage()` 中 `_renderDayCache._gen` 使用 `state.updatedAt`；由于 `updatedAt` 在每次 commit（编辑大纲正文、切换折叠态）都单调递增，**日历待办实际不变时也整表失效**，日历每次重渲染都重建 2000 条 LRU。目标：**日历数据不变则不重建，日历数据变化才重建**。
- **范围**：仅 [`canonical`](../../6.P0-L3基线/v2.0-l3.html.html:1) + step9 镜像 + 登记 / 门禁口径 + 波报告 / 证据；**不新增纳编物**（登记方数保持 **43**）。

## 二、实现（失效粒度解耦）

### 2.1 新增独立代次与选择态签名（canonical L2131–L2137）

在模块级缓存声明区新增：

```js
let _calDataRev=0;   /* 日历数据代次 */
let _calSelKey='';   /* 上次渲染的日历选择态签名（selectedDate|calTagFilter） */
```

- `_calDataRev` **仅在**「日历数据失效」或「选择态变化」时递增，**不**随 `state.updatedAt` 变化。

### 2.2 代次推进点（全部 `_calIndexCache` 失效接缝）

| # | 位置 | 处置 |
|---|---|---|
| 1 | [`invalidateCalIndex()`](../../6.P0-L3基线/v2.0-l3.html.html:2145)（主失效入口） | `_calDataRev++`（与 `_calIndexCache=null` 同步） |
| 2 | `mergeRemoteState` finally（[:1903](../../6.P0-L3基线/v2.0-l3.html.html:1903)） | `_calDataRev++` |
| 3 | `reportIndexFailure` 连续失败兜底（[:3090](../../6.P0-L3基线/v2.0-l3.html.html:3090)） | `_calDataRev++` |
| 4 | `l6InjectionFailure` 降级出口（[:3113](../../6.P0-L3基线/v2.0-l3.html.html:3113)） | `_calDataRev++` |
| 5 | `commit` 增量索引失败 / 删除失败（[:4294](../../6.P0-L3基线/v2.0-l3.html.html:4294) / [:4303](../../6.P0-L3基线/v2.0-l3.html.html:4303)） | `_calDataRev++` |
| 6 | `undo` / `redo` 增量索引失败（[:4660](../../6.P0-L3基线/v2.0-l3.html.html:4660) / [:4698](../../6.P0-L3基线/v2.0-l3.html.html:4698)） | `_calDataRev++` |
| 7 | `desktopReloadIntoApp` 快照重载（[:18716](../../6.P0-L3基线/v2.0-l3.html.html:18716)） | `_calDataRev++` |

> **口径**：凡 `_calIndexCache` 被置空 / 日历索引失效处，**均**同步推进 `_calDataRev`（全仓 **10** 处 `_calDataRev++`），保证「索引失效 ⇒ 日缓存失效」语义不破。

### 2.3 渲染代次判定（canonical L9028–L9035）

```js
const _calSelKeyNow=(ui.selectedDate||'')+'|'+(ui.calTagFilter||'');
if(_calSelKeyNow!==_calSelKey){_calSelKey=_calSelKeyNow;_calDataRev++;}
if(!_renderDayCache||_renderDayCache._gen!==_calDataRev)_renderDayCache={_gen:_calDataRev,map:makeLRU(2000)};
```

- **选择态变化**（`selectedDate` / `calTagFilter`）在渲染入口一次性检测并推进代次，覆盖全部 UI 变更点（无需逐点埋桩）。
- **`_gen` 口径更换**：由 `state.updatedAt` → `_calDataRev`。

### 2.4 降级 / 兜底（红线守持）

- **非优化分支不变**：`__l14On()=false` / `_vsUserDisabled=true` / `IS_DESKTOP=false` 路径与其无关（本改仅涉及渲染缓存代次），行为逐字节等价。
- **保守二次守卫保留**：`commit` 的 `touched` / `_clearWC` 分支与 `undo` / `redo` 仍保留 `_renderDayCache=null`（内容变更时立即失效），**不放宽**任何既有失效条件。
- **冻结 API / 数据契约**：`window.__ju*` 探针方法名与返回形状、`state.nodes` 结构、`juju.store.v31` 形状、加密 payload 字段名**均零变更**。
