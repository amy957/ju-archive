## 一、为什么保留重复副本

`1.历史归档/1.1冻结版本/`（含 `legacy-pre-tail-removal/` 子目录）中存在 3 组逐字节完全相同的 HTML 冻结件。它们**不是**误拷贝，而是
历史波次（t8/t9/t10/t11、v2.0-frozen）各自独立封存时留下的只读锚点：

- 每个副本都被当时的验收/冻结脚本按“独立文件名”登记过，直接删除会让历史报告与
  归档清单（`_报告与元数据/ARCHIVE-INDEX.md`）中的路径失效，并造成不可追溯。
- 门禁（`6.P0-T3基线/step9/verify-hash-registry.mjs`、`scripts/_w5freeze.ps1`）按
  文件名 + SHA-256 逐一比对，保留重复件不影响零漂移判定。

因此采取**等量保留 + 就地别名说明**的处置：不删除、不合并、不重命名，仅在本文件
登记同源关系，消除“为何存在重复件”的信息缺口。

## 三、同源判定与使用约定

1. 上表每一组内，两个文件的字节数与 SHA-256 **完全一致**，互为别名（alias），
   内容不存在分叉风险。
2. 别名关系为**历史事实**，不表示可以互相替代登记：门禁与索引仍按各自文件名核验，
   任何一方字节变化都必须单独报告漂移。
3. 后续如需“等量置换/去重”，必须先在 `_报告与元数据/FIX-BACKLOG.md` 立项并记录
   决策编号，再同步更新 `ARCHIVE-INDEX.md` 与登记器，禁止直接删除本目录文件。
4. 本文件本身不属于冻结产物，可随说明修订；冻结 HTML 一律只读。
